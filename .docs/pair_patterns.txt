《默契研究所 V2.0》
双人互动模式库｜25 组 Pair Interaction Patterns
版本：V2.0-PAIR-001
核心原则：
双人报告不是：
A 是什么人
B 是什么人
两个结果加起来
而是：
A 的某种反应，如何触发 B；B 的反应，又如何反过来触发 A。
因此每个模式必须包含：
触发条件
A 的主观体验
B 的主观体验
循环怎么形成
这个组合的优势
风险
什么时候不是问题
什么时候会被放大
给 A 的建议
给 B 的建议
双方可直接使用的一句话
Pattern 01｜靠近 — 撤离循环
代码：
APPROACH_WITHDRAW
触发：
A：
response_need >= 70
并且：
conflict_urgency >= 60
B：
space_need >= 70
并且：
conflict_urgency <= 45
A 的体验：
“你越不回应，我越需要确认。”
B 的体验：
“你越逼近，我越需要先离开一点。”
循环：
A 感到不确定
→ A 增加联系
→ B 感到压力
→ B 后退
→ A 更不安
→ A 进一步靠近
→ B 进一步撤离
优势：
A 会主动维护连接。
B 能在压力中暂停升级。
风险：
双方的自我保护方式正好互相触发。
什么时候不是问题：
B 能明确说明：
“我需要暂停多久。”
A 能接受：
“暂停不等于离开。”
给 A：
把“你为什么又躲开”改成“我需要知道我们什么时候继续聊”。
给 B：
不要只撤离，要给“返回时间”。
双方话术：
“我们先停一下，但不是结束。今晚九点我们继续。”
Pattern 02｜双高回应需求
代码：
HIGH_RESPONSE_BOTH
触发：
A、B：
response_need >= 70
表现：
双方都很在意回复、联系、主动程度。
优势：
连接感强。
双方通常都愿意主动。
风险：
任何一方进入忙碌期，都容易被另一方理解成关系变化。
循环：
联系减少
→ 一方不安
→ 另一方察觉到不安，也开始不安
→ 双方互相确认
→ 短暂缓解
→ 对联系稳定性的依赖进一步增加
建议：
建立明确的“低联系日”规则。
话术：
“今天我们都忙，回复慢不是关系信号。”
Pattern 03｜双高空间需求
代码：
HIGH_SPACE_BOTH
触发：
A、B：
space_need >= 70
优势：
彼此通常不容易觉得被控制。
都能保留个人生活。
风险：
双方都太能独立，可能没人主动创造连接。
循环：
A 忙自己的
→ B 也忙自己的
→ 两个人都觉得“没问题”
→ 共同经历越来越少
→ 关系在没有冲突的情况下慢慢变淡
建议：
不要只靠“有事再联系”。
需要主动创造固定连接。
话术：
“我们都很独立，所以更需要主动留一些只属于我们的时间。”
Pattern 04｜高敏感 × 低敏感
代码：
HIGH_LOW_SENSITIVITY
触发：
A：
emotional_sensitivity >= 75
B：
emotional_sensitivity <= 40
A 体验：
“这么明显你怎么会看不出来？”
B 体验：
“你为什么总能从小事情里读出这么多？”
优势：
A 能捕捉细节。
B 不容易被小变化带走。
风险：
A 觉得 B “不在乎”。
B 觉得 A “过度解读”。
建议 A：
不要把“我察觉到了”直接升级为“所以一定有问题”。
建议 B：
不要否定 A 的感知。
话术：
“我知道你注意到了变化，我先告诉你它是不是和我们有关。”
Pattern 05｜双高敏感
代码：
HIGH_SENSITIVITY_BOTH
触发：
双方：
emotional_sensitivity >= 75
优势：
非常容易理解细节。
共情能力可能强。
风险：
两个人都很容易被语气、表情、沉默带动。
循环：
A 状态变化
→ B 察觉
→ B 自己也变化
→ A 又察觉 B 的变化
→ 情绪互相放大
建议：
增加“事实确认”环节。
话术：
“我们先确认发生了什么，再解释它意味着什么。”
Pattern 06｜高表达 × 低表达
代码：
DIRECT_INDIRECT
触发：
A：
expression >= 70
B：
expression <= 40
A 体验：
“有问题为什么不能直接说？”
B 体验：
“不是所有感受都能马上说清楚。”
优势：
A 推动关系明确。
B 会给情绪留消化空间。
风险：
A 觉得 B 隐瞒。
B 觉得 A 逼迫。
建议 A：
允许“不确定答案”。
建议 B：
即使没想清楚，也先表达状态。
话术：
“我现在还没想明白，但我不是不想和你谈。”
Pattern 07｜双低表达
代码：
LOW_EXPRESSION_BOTH
触发：
双方：
expression <= 45
优势：
冲突表面可能不多。
风险：
很多问题不是解决了，而是没人说。
循环：
A 不舒服但不说
→ B 也察觉不到
→ B 有不满也不说
→ 双方表面正常
→ 怨气慢慢累积
→ 最后因为小事突然爆发
建议：
建立固定关系复盘时间。
话术：
“最近有没有什么小事，其实你一直没说？”
Pattern 08｜立即解决 × 延后处理
代码：
SOLVE_NOW_PAUSE
触发：
A：
conflict_urgency >= 70
B：
conflict_urgency <= 40
A：
“不解决我根本放不下。”
B：
“现在继续只会更糟。”
风险：
A 把暂停理解成逃避。
B 把继续沟通理解成逼迫。
关键：
给暂停一个明确结束点。
话术：
“我们不是不谈，是今晚十点继续谈。”
Pattern 09｜双高冲突紧迫
代码：
HIGH_CONFLICT_URGENCY_BOTH
触发：
双方：
conflict_urgency >= 70
优势：
问题通常不会长期悬着。
风险：
双方情绪高点都想解决，容易升级。
建议：
建立“暂停阈值”。
话术：
“如果任何一方开始重复、提高音量或攻击人格，我们暂停 30 分钟。”
Pattern 10｜双低冲突紧迫
代码：
LOW_CONFLICT_URGENCY_BOTH
触发：
双方：
conflict_urgency <= 40
优势：
不容易爆炸式争吵。
风险：
双方都觉得“以后再说”，最后没人回来。
建议：
暂停必须附带重启时间。
Pattern 11｜高修复 × 低修复
代码：
REPAIR_MISMATCH
触发：
A：
repair_orientation >= 70
B：
repair_orientation <= 45
A：
“有问题就修，我们还能调整。”
B：
“发生过的事情不会因为一次沟通就消失。”
风险：
A 觉得 B 不给机会。
B 觉得 A 太快翻篇。
建议：
A 不要催“赶紧和好”。
B 要明确修复需要什么条件。
话术：
“我不是不想修，我需要看到哪些变化以后才能重新靠近。”
Pattern 12｜双高修复
代码：
HIGH_REPAIR_BOTH
触发：
双方：
repair_orientation >= 70
优势：
关系韧性强。
风险：
过度强调修复，可能长期容忍同一个结构问题。
特别检测：
repeated_pattern_erosion
如果双方都高：
报告必须提醒：
“能和好，不代表问题已经解决。”
Pattern 13｜安全感来自语言 × 来自行动
代码：
WORDS_ACTIONS
触发：
A：
verbal_reassurance_need 高
B：
care_action_vs_affection_expression 偏行动
A：
“为什么你从来不说？”
B：
“我做这么多你看不到吗？”
优势：
双方其实都在表达在乎。
风险：
爱的证据语言不一致。
建议：
双方学习“翻译”。
话术：
A：
“我看见你做的这些事，同时我也会因为听到你表达而更安心。”
B：
“我不是只说，我也愿意偶尔让你听见。”
Pattern 14｜高仪式感 × 低仪式感
代码：
RITUAL_MISMATCH
触发：
A：
ritual_need 高
B：
ritual_need 低
A：
“这不是礼物，是你有没有把这件事放在心上。”
B：
“感情又不是靠节日证明。”
真正冲突：
不是礼物。
是“被记住”的意义不同。
建议：
定义双方最低仪式标准。
Pattern 15｜高隐私 × 高透明
代码：
PRIVACY_TRANSPARENCY
触发：
A：
privacy_boundary / privacy_boundary_long_term 高
B：
transparency_need / social_transparency_need 高
A：
“有隐私不代表我有秘密。”
B：
“主动分享才让我觉得自己真正进入你的生活。”
风险：
透明被理解成监控。
隐私被理解成隐藏。
建议：
区分：
隐私
秘密
报备
监控
话术：
“我们可以约定什么属于正常分享，什么属于个人空间。”
Pattern 16｜高嫉妒 × 高信任
代码：
JEALOUS_BUT_TRUSTING
触发：
jealousy_source = 情绪反应
同时：
trust indicators 高
解释：
一个人可以会吃醋，同时仍然信任对方。
不要写：
“你控制欲强。”
建议：
允许情绪存在，但不把情绪直接变成限制。
Pattern 17｜关系优先级期待差异
代码：
PRIORITY_EXPECTATION_GAP
触发：
A：
relationship_priority_expectation 高
B：
较低
A：
“在一起以后，你的安排应该自然把我放得更前。”
B：
“恋爱不应该让朋友、工作和原本生活全部改变。”
风险：
A 看成“不够重视”。
B 看成“要求太多”。
建议：
不要争“谁应该第一”。
谈：
哪些情境必须优先。
Pattern 18｜共同生活融合 × 高独立
代码：
INTEGRATION_AUTONOMY
触发：
A：
life_integration_preference 高
B：
space_need 高 / life_integration_preference 低
A：
“长期在一起就应该越来越共享生活。”
B：
“长期承诺不等于失去自己的生活结构。”
优势：
A 能建构共同体。
B 能保护个人完整性。
建议：
建立：
共同区
个人区
Pattern 19｜未来明确需求差异
代码：
FUTURE_CLARITY_GAP
触发：
A：
future_clarity_need / long_horizon_alignment_need 高
B：
低
A：
“如果不谈未来，我不知道自己为什么继续投入。”
B：
“未来变化太多，现在说也没有意义。”
真正需要区分：
A 是否需要结果保证，
还是只需要愿意讨论。
如果：
dialogue_over_guarantee 高
报告应写：
A 真正要的不是承诺结果，而是被纳入未来思考。
Pattern 20｜金钱公平模型冲突
代码：
FINANCIAL_FAIRNESS_GAP
触发：
双方 financial_fairness_model 差异明显
例如：
A：
50/50
B：
按收入比例
风险：
双方都觉得自己追求公平。
但公平定义不同。
建议：
先谈：
公平是什么意思。
再谈数字。
Pattern 21｜家务公平模型冲突
代码：
HOUSEHOLD_FAIRNESS_GAP
触发：
A、B：
household_fairness_model 不同
可能：
A 看数量。
B 看总负担。
再结合：
mental_load_awareness
如果一方高，一方低：
出现：
“我明明做了很多”
vs
“可为什么所有事情还是我记着？”
核心句：
你们争的可能不是谁做得多，而是谁负责让整个家正常运转。
Pattern 22｜情绪劳动失衡
代码：
EMOTIONAL_LABOR_IMBALANCE
触发：
A：
household_emotional_load / support burden 高
B：
情绪输出明显高
A：
“为什么每次你的情绪最后都变成我要处理？”
B：
“我只是希望最亲近的人支持我。”
风险：
支持慢慢变成责任。
建议：
B 要表达：
“我只是想被听见，不需要你解决。”
A 要允许：
“我现在没有足够精力接住。”
Pattern 23｜主动修复失衡
代码：
REPAIR_LABOR_GAP
触发：
一方：
repair_labor_imbalance
或：
relationship_maintenance_imbalance
高
循环：
A 先联系
→ A 提问题
→ A 主动和好
→ B 配合
→ A 越来越感觉“所有关系工作都是我做”
关键追问：
B 是不主动发起，
还是根本不参与后续修复？
两者要分开。
Pattern 24｜老关系中的“旧版本理解”
代码：
OUTDATED_PARTNER_MODEL
触发：
长期关系
growth_alignment_need 高
一方对另一方变化接受低
表现：
“你以前不是这样的。”
风险：
双方用过去版本解释现在的人。
建议：
重新认识。
话术：
“如果我们今天刚认识，你觉得我现在是一个什么样的人？”
Pattern 25｜修复窗口仍在，但方法失效
代码：
REPAIR_WINDOW_METHOD_FAILURE
适用：
关系紧张模式。
触发：
双方：
repair_willingness_remaining 中高
baseline_respect_remaining 中高
但：
communication_futility 高
pseudo_repair 高
解释：
你们的问题可能不是“不想修”。
而是已经把同一种无效方法重复用了很多次。
风险：
继续“再谈一次”只会增加疲劳。
建议：
必须改变修复结构，而不是增加修复次数。
核心句：
不是再认真一点沟通，而是换一种沟通方式。
三、双人模式不能只检测“差异”
这一点非常重要。
有三种模式来源：
类型 A：差异模式
例如：
高回应 × 高空间
类型 B：相似放大模式
例如：
双方都高敏感。
双方都高冲突紧迫。
类型 C：系统性模式
例如：
一个长期承担修复。
另一个总是配合但不主动。
所以 pair engine 不能只是：
abs(A - B)
四、程序的数据结构
建议：
export interface PairPattern {
id: string;
name: string;
category:
| "difference"
| "similarity"
| "system";
trigger: PairPatternTrigger;
priority: number;
minimumConfidence: number;
explanation: {
personAExperience: string;
personBExperience: string;
cycle: string[];
strength: string;
risk: string;
whenHealthy: string;
amplificationConditions: string[];
adviceA: string[];
adviceB: string[];
sharedScript: string;
};
}
五、模式置信度
每个模式输出：
{
"pattern": "APPROACH_WITHDRAW",
"confidence": 91,
"severity": 74,
"direction": {
"approacher": "A",
"withdrawer": "B"
}
}
注意：
confidence
和：
severity
不是一回事。
Confidence：
我们有多确定模式存在。
Severity：
这个模式现在影响关系有多大。
六、Severity 怎么算
例如：
追逐—撤离：
severity =
A.response_need intensity × 0.25
+
B.space_need intensity × 0.25
+
A.conflict_urgency × 0.15
+
B.low_conflict_urgency × 0.15
+
recurrence signal × 0.20
如果只是性格差异，但用户说：
“其实我们几乎不因为这个吵。”
则：
severity 应下降。
七、同一个用户最多展示几个核心模式
不要：
你们有 17 个模式。
报告会变成垃圾。
建议完整双人报告：
主模式
1 个。
次模式
2–3 个。
优势模式
1–2 个。
例如：
主模式：
靠近—撤离循环
次模式：
未来明确需求差异
表达节奏差异
优势：
双方修复意愿都高
这样用户容易理解。
八、主模式排名公式
建议：
pair_pattern_rank =
confidence × 0.30
+
severity × 0.35
+
recurrence × 0.20
+
report_relevance × 0.15
九、优势也必须检测
我们的报告不能只找问题。
例如：
优势 01
双方：
repair_orientation >= 70
输出：
你们关系里一个很明显的优势，是双方都没有把冲突自动理解成关系结束。
优势 02
一个高敏感，一个低敏感，但两个人表达都高。
输出：
一个人能注意细节，一个人能够降低情绪波动，只要双方愿意解释，这种差异反而可能互补。
优势 03
双方高自主 + 高未来承诺。
输出：
你们可能很适合“独立但稳定”的关系结构。
十、双人报告推荐结构
01｜你们是什么组合
例如：
「靠近者 × 整理者」
02｜这段关系天然的优势
2–3 点。
03｜最重要的互动循环
重点解释主模式。
04｜A 看见的世界
例如：
A 感受到的是“不确定”。
05｜B 看见的世界
例如：
B 感受到的是“压力”。
06｜为什么双方都觉得自己有道理
这是非常重要的一章。
07｜这个循环是如何一步一步形成的
最好做图：
A 不安
↓
靠近
↓
B 压力
↓
撤离
↓
A 更不安
08｜什么时候它不会成为问题
让报告不是宿命论。
09｜什么情况下它会被放大
例如：
疲劳。
异地。
工作压力。
关系不确定。
过去信任受损。
10｜A 可以做什么
具体。
11｜B 可以做什么
具体。
12｜双方下一次可以直接这样说
提供 3 个真实话术。
十一、严禁这样写
禁止：
A 是焦虑型。
B 是回避型。
除非未来使用经过专业授权和验证的正式依恋量表。
目前我们的语言应该是：
当关系出现不确定时，A 更倾向靠近确认；B 更倾向先获得空间。
描述行为。
不要临床化、人格化。
十二、双人模式的核心哲学
《默契研究所》最重要的一个观点应该是：
很多关系问题，并不是一个人有问题。
而是一个人的保护方式，恰好触发了另一个人的保护方式。
这句话应该成为整个双人报告引擎的核心。

7. 年龄 / 生活阶段变体
这一块不是重新创造心理维度。
而是把现在所有母题“翻译”成不同年龄真正经历的生活。
建议建立：
18–24 岁
25–34 岁
35–44 岁
45+ 岁
每个阶段至少：
20–30 个高频生活场景标签。

TA 周末宁愿和室友、同学出去……
25–34：
TA 难得休息一天，却优先安排朋友或工作……
35–44：
工作、孩子、父母事情很多以后，你发现彼此永远排在最后……
45+：
双方已经建立稳定生活节奏，一方逐渐把更多时间投入自己的社交或兴趣……
底层仍然测同一件事。
但用户看到的是：
自己的生活。
