《默契研究所 V2.0》
统一动态追问题库 40 题 + 触发规则
版本：V2.0-FU-CORE-001
用途：
这是《默契研究所》动态测试引擎的核心规则层。
目标不是：
多问几道题。
而是：
当系统发现用户前面的回答存在“矛盾、模糊、可产生多种解释”时，主动选择最有信息价值的下一题。
正式测试中：
前 20 题完成
↓
计算初步六维分数
↓
检测隐藏信号
↓
检测矛盾组合
↓
评估当前最不确定的 4 个结论
↓
从以下 40 道追问题中选 4 道
↓
完成最终 24 题
↓
重新评分
↓
生成报告
一、动态追问必须解决什么问题
举例。
用户前 20 题显示：
回应需求：82
空间需求：78
不能直接写：
你既黏人又独立。
这是低质量分析。
系统应该先问：
“如果对方明确告诉你关系没有问题，你是否就能安心享受自己的空间？”
如果回答高：
结论变成：
高空间需求 + 高确定感需求。
如果回答低：
则可能意味着：
高联系需求 + 个人空间需求同时存在。
完全不是一回事。
所以动态追问承担的是：
「消除歧义。」
二、追问优先级模型
每个候选追问题计算：
information_gain_score
建议：
information_gain_score =
pattern_uncertainty × 0.40
+
report_impact × 0.30
+
confidence_gap × 0.20
+
relationship_relevance × 0.10
其中：
pattern_uncertainty
当前模式是否存在两种以上解释。
0–100。
report_impact
这道题答案是否会明显改变最终报告。
0–100。
confidence_gap
现有数据对这个判断是否还不够稳定。
0–100。
relationship_relevance
它是否和当前关系状态高度相关。
0–100。
最终：
选择最高的 4 道。
三、追问不得重复确认已经很确定的结论
如果：
回应需求连续 5 道题全部高分，
而且不存在矛盾信号，
不要继续问：
“你是不是很需要回应？”
这是浪费题目。
追问应该优先问：
为什么需要回应？
例如：
需要联系本身？
需要确定关系？
需要被优先考虑？
害怕失去？
对方过去确实反复失联？

五、程序触发规则
每个追问题应增加：
interface FollowupQuestion {
id: string;
text: string;
trigger: {
minScores?: Partial<DimensionScores>;
maxScores?: Partial<DimensionScores>;
requiredSignals?: string[];
anySignals?: string[];
relationshipTypes?: string[];
relationshipStages?: string[];
};
resolves: string[];
reportImpact: number;
exclusionGroup?: string;
}
例如：
{

六、追问选择算法
伪代码：
function chooseDynamicFollowups(
result: PreliminaryResult,
context: AssessmentContext,
allQuestions: FollowupQuestion[]
) {
const candidates =
allQuestions.filter(question =>
triggerMatches(
question.trigger,
result,
context
)
);
const scored =
candidates.map(question => ({
question,
score:
calculatePatternUncertainty(
question,
result
) * 0.40 +
question.reportImpact * 0.30 +
calculateConfidenceGap(
question,
result
) * 0.20 +
calculateRelationshipRelevance(
question,
context
) * 0.10
}));
scored.sort(
(a, b) => b.score - a.score
);
return enforceDiversity(
scored,
4
);
}
